Chapter 4Looking Inside Files

Almost everything on a Linux system is a text file: configuration, logs, data, scripts. Knowing four or five ways to read them — and which one fits the situation — removes any need to open a GUI editor to glance at something.

Reading whole files

$ cat notes.txt              # dump the whole file to the screen
$ cat -n script.sh           # with line numbers
$ cat a.txt b.txt > both.txt # concatenate — this is what "cat" is short for
$ less /var/log/syslog       # page through it interactively

Use cat for short files and less for anything you cannot see in one screen. less does not load the whole file into memory, so it opens a 4 GB log instantly.

In lessDoes
Space / bpage down / page up
g / Gjump to start / end of file
/wordsearch forward; n next match, N previous
&wordshow only lines matching — a hidden gem for logs
Ffollow the file as it grows, like tail -f; Ctrl-C to stop
qquit

Reading parts of files

$ head data.csv              # first 10 lines
$ head -n 3 data.csv         # first 3
$ tail -n 50 app.log         # last 50
$ tail -f app.log            # keep printing new lines as they arrive
$ tail -F app.log            # same, but survive log rotation
$ head -n 20 file | tail -n 5    # lines 16-20

tail -f is how you watch a service while you poke at it. Leave it running in one terminal, do the thing in another. Combine it with grep to watch only what matters:

$ tail -f app.log | grep --line-buffered ERROR

Counting and measuring

$ wc -l access.log        # how many lines
128473 access.log
$ wc -w essay.txt         # words
$ wc -c image.png         # bytes
$ file mystery            # what kind of file is this, really?
mystery: PNG image data, 1200 x 800, 8-bit/color RGBA
$ stat notes.txt          # size, timestamps, permissions, inode

file looks at the content, not the extension — useful when someone hands you data.txt that is actually a gzip archive.

Comparing

$ diff old.conf new.conf         # line-by-line differences
$ diff -u old.conf new.conf      # unified format — the same format git uses
$ diff -r dir1/ dir2/            # compare whole trees
$ cmp a.bin b.bin                # byte comparison, for binaries
$ md5sum file                    # fingerprint, to check two copies match
$ diff -u old.conf new.conf
--- old.conf
+++ new.conf
@@ -3,5 +3,5 @@
 listen 80;
-worker_processes 2;
+worker_processes 4;
 keepalive_timeout 65;

Lines with - are in the first file, + in the second, and unmarked lines are context. Once you can read a unified diff you can read every code review you will ever be sent.

When it is not text

$ strings binary_file | less      # pull out the readable text
$ xxd file | head                 # hex dump
$ zcat archive.gz | less          # read a gzipped file without unpacking it
$ zgrep ERROR app.log.2.gz        # grep inside a gzipped file
Tip

Never cat a binary file. It will send control characters to your terminal and leave the display garbled. If you do, reset fixes it.

Questions

Why prefer less over cat for a large log?

cat writes the entire file to your terminal, which scrolls almost all of it past you and can take a long time for a multi-gigabyte file. less reads only the part it is displaying, so it opens instantly regardless of size, and it gives you search and navigation. The only real reason to cat a big file is to pipe it somewhere else — and even then you usually do not need cat at all (see the next question).

What is wrong with cat file.txt | grep ERROR?

Nothing breaks, but it starts an extra process for no reason — grep can open the file itself: grep ERROR file.txt. This is common enough to have a name, the "useless use of cat". It is a small thing, but on a loop over 10,000 files it stops being small.

What is the difference between tail -f and tail -F?

-f follows the open file descriptor. If logrotate renames app.log to app.log.1 and creates a fresh app.log, -f keeps watching the old, now-renamed file and goes silent. -F follows the name, so it notices the rotation and reattaches. On a long-running watch, use -F.

How do you print lines 100-110 of a file?

head -n 110 file | tail -n 11 is the portable answer and the one most people reach for. sed -n '100,110p' file is more direct and stops reading early if you add -n '100,110p;110q'. Both are fine; the head/tail version is easier to remember under pressure.

A colleague sends you config.txt and your editor shows gibberish. What do you run first?

file config.txt. Extensions on Linux are decoration; file inspects the actual bytes and will tell you it is a gzip archive, a JPEG, or UTF-16 text. Then act accordingly — zcat, an image viewer, or iconv.
