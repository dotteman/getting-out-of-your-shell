Chapter 12Working Fast

The last 20% is not new commands — it is the friction between you and the ones you know. This chapter is a collection of things that each save a few seconds, several dozen times a day.

Editing the command line

Bash uses readline, which has emacs keybindings by default. These work at every bash prompt and in most REPLs (psql, python, node):

KeysDoes
Ctrl-A / Ctrl-Ejump to start / end of line
Alt-B / Alt-Fback / forward one word
Ctrl-Wdelete the word before the cursor
Ctrl-U / Ctrl-Kdelete to start / end of line
Ctrl-Ypaste back what you just deleted
Ctrl-Rreverse search through history
Ctrl-Lclear the screen
Ctrl-C / Ctrl-Dcancel this line / end of input
Alt-.insert the last argument of the previous command

Two of these carry most of the value. Ctrl-R to find any command you have run before, and Ctrl-U then Ctrl-Y to stash a half-typed command, run something else, then paste it back.

History expansion

$ sudo !!               # rerun the last command with sudo
$ !$                     # the last argument of the previous line
$ mkdir /a/long/path && cd !$      # ...becomes cd /a/long/path
$ ^typo^fixed            # rerun the last command with one substitution
$ !ssh                   # last command that started with ssh
$ !ssh:p                 # print it without running it — check before you leap

Archives and transfers

$ tar -czf archive.tar.gz dir/     # create gzipped archive
$ tar -xzf archive.tar.gz          # extract
$ tar -tzf archive.tar.gz          # list contents without extracting
$ tar -xzf archive.tar.gz -C /dest # extract somewhere specific

$ scp file.txt user@host:/path/    # copy to a remote machine
$ scp user@host:/path/file.txt .   # copy from one
$ rsync -avz --progress src/ user@host:/dest/   # sync, resumable, only changes
$ rsync -avz --dry-run src/ dest/  # show what WOULD happen

Remember tar's flags as a sentence: create or extract or list, z for gzip, f for "the filename follows". -f must come last because the filename is its argument.

rsync beats scp for anything nontrivial: it transfers only the differences, resumes after an interruption, and --dry-run lets you check first. The trailing slash on the source means "the contents of", and getting it wrong is the classic rsync mistake.

Network basics

$ curl -s https://api.example.com/status | jq .
$ curl -I https://example.com                  # headers only
$ curl -fsSL -o file.tar.gz https://host/f.tgz # fail loudly, follow redirects
$ curl -X POST -H "Content-Type: application/json" \
       -d '{"key":"value"}' https://api.example.com/items

$ ssh user@host                       # log in
$ ssh user@host 'df -h'               # run one command and come back
$ ssh -i ~/.ssh/id_ed25519 user@host  # with a specific key
$ ssh-copy-id user@host               # install your key so you stop typing passwords

$ ss -tulpn        # listening ports
$ dig example.com +short
$ ping -c 4 example.com
$ traceroute example.com

curl -fsSL is worth memorizing as a unit: fail on HTTP errors instead of saving the error page, silent, Show errors anyway, L follow redirects.

SSH config

Put this in ~/.ssh/config and stop retyping connection details:

Host prod
    HostName 10.0.4.21
    User deploy
    IdentityFile ~/.ssh/id_prod
    ServerAliveInterval 60

Host *.internal
    User admin
    ProxyJump bastion.example.com
$ ssh prod          # instead of ssh -i ~/.ssh/id_prod deploy@10.0.4.21

Tab completion works on these host names, and scp, rsync, and git all respect the file too.

Scheduling

$ crontab -e         # edit your scheduled jobs
$ crontab -l         # list them
# ┌─ minute (0-59)
# │ ┌─ hour (0-23)
# │ │ ┌─ day of month (1-31)
# │ │ │ ┌─ month (1-12)
# │ │ │ │ ┌─ day of week (0-6, Sunday = 0)
# │ │ │ │ │
  0 2 * * *   /home/dave/bin/backup.sh >> /var/log/backup.log 2>&1
  */15 * * * * /home/dave/bin/check.sh
  0 9 * * 1   /home/dave/bin/weekly-report.sh

Three rules that prevent the usual cron pain: use absolute paths for everything, redirect output to a log file (otherwise it is emailed into the void), and test the script by running it with a stripped environment first: env -i /bin/bash --noprofile --norc /path/to/script.sh.

A handful of things worth knowing exist

$ !!                      # you know this one now
$ cd -                     # previous directory
$ pushd /tmp ; popd        # a directory stack, for hopping around
$ time ./slow.sh           # how long did that take
$ watch -n2 'df -h /'      # rerun a command every 2 seconds
$ yes | some-command       # answer y to everything
$ seq 1 10                 # generate a sequence
$ shuf -n 5 lines.txt      # random sample
$ column -t -s, data.csv   # align CSV into readable columns
$ jq '.items[].name' r.json # query JSON properly
$ base64 -w0 file          # encode
$ openssl rand -hex 16     # a random token
$ df -h; free -h; uptime   # the three-command health check
The compounding habit

Every time you type a long command a second time, stop and decide: alias, function, or script? A one-liner you use daily becomes an alias. A parameterized one becomes a shell function in .bashrc. Anything longer than five lines becomes a script in ~/bin. Twenty minutes spent on this in your first month pays back for years.

Where to go from here

You now have the 20%. The natural next steps, roughly in order of payoff:

  • tmux — persistent sessions and split panes. An afternoon to learn, permanent benefit.
  • vim or nano — you will eventually need to edit a file on a machine with nothing else. Learn enough vim to open, edit, save, and quit: i to insert, Esc, :wq to write and quit, :q! to bail out.
  • ripgrep, fd, fzf, bat — modern replacements for grep, find, and cat. fzf in particular transforms Ctrl-R.
  • shellcheck — install it, run it on everything you write.
  • jq — once your pipelines start touching APIs, jq is to JSON what awk is to columns.
  • Bash Pitfalls and the Bash FAQ — the best free references for the things that will bite you.

Questions

What is the difference between scp and rsync?

scp copies everything, every time, and starts over if interrupted. rsync compares source and destination and transfers only the differences, can resume, preserves permissions and timestamps with -a, compresses in flight with -z, and offers --dry-run. For a single small file scp is fine; for a directory or anything you will repeat, use rsync.

Why does a cron job fail when the same script works from your shell?

Cron gives the job a nearly empty environment: a minimal PATH, no .bashrc, no DISPLAY, and the home directory as the working directory. Anything your interactive shell set up for you is absent. Diagnose it by capturing output — add >> /tmp/job.log 2>&1 to the crontab line — and fix it by setting PATH at the top of the script and using absolute paths throughout.

What do the flags in tar -xzf mean, and why must -f come last?

x extract, z decompress with gzip, f the archive filename follows. -f takes the next word as its argument, so anything after it is treated as the filename. tar -xfz archive.tar.gz tries to open a file literally named z.

You need to run a 6-hour job on a remote server over a flaky connection. What do you do?

SSH in, start tmux (or screen), run the job inside it, and detach with Ctrl-b d. The session keeps running on the server independently of your connection; reattach later with tmux attach. nohup job & also survives the disconnect but gives you no way to interact with the job afterwards, which matters when it prompts or when you want to watch it.

What is the single fastest way to reuse a command you ran an hour ago?

Ctrl-R, then type any distinctive fragment of it — press Ctrl-R again to step further back through matches, Enter to run, or → to load it into the line for editing. It beats pressing ↑ forty times and beats history | grep because it puts the result straight onto your command line.
