Chapter 1The Shell in Ten Minutes

The shell is a program that reads what you type, runs it, and prints the result. That is the whole idea. When you open a terminal you get a shell — usually bash — sitting in a loop, waiting.

What makes it worth learning is not any single command. It is that every command is a small tool that reads text and writes text, and the shell lets you connect them. Once you internalize that, a hundred commands become a combinatorial toolkit instead of a hundred things to memorize.

Reading the prompt

A typical prompt looks like this:

dave@web-01:~/projects/api$

Four pieces of information: your username, the machine you are on, the directory you are in (~ means your home directory), and a $ meaning you are an ordinary user. A # instead of $ means you are root — pay attention when you see it.

Anatomy of a command

$ ls -l --color=auto /var/log
  │   │       │          │
  │   │       │          └─ argument: what to operate on
  │   │       └─ long option with a value
  │   └─ short option (flags can bundle: -la is -l -a)
  └─ the command

Three rules cover nearly all syntax you will meet:

  • Whitespace separates arguments. rm my file.txt deletes two files, not one. Quote names with spaces: rm "my file.txt".
  • Short options are single letters with one dash and can be combined: ls -l -a -h equals ls -lah. Long options use two dashes and are not combinable: --human-readable.
  • Order usually does not matter for options, but arguments are positional: cp SOURCE DEST is not the same as cp DEST SOURCE.

The first six commands

$ pwd              # where am I?
/home/dave
$ ls               # what is here?
Documents  Downloads  projects  notes.txt
$ cd projects      # go somewhere
$ whoami           # who am I logged in as?
dave
$ date             # what time is it (on this machine)?
Fri Aug 14 09:12:44 PDT 2026
$ clear            # wipe the screen (Ctrl-L does the same)

Getting help without leaving the terminal

You will not remember every flag, and you are not supposed to. Learn the three ways to look things up instead.

CommandWhat it gives you
man lsThe full manual page. Press / to search, n for next match, q to quit.
ls --helpA one-screen summary. Faster than man for "what was that flag again?"
help cdFor shell builtins like cd, export, if — these have no man page of their own.
type lsTells you whether something is a builtin, an alias, a function, or a program on disk.
apropos compressSearches man page descriptions when you don't know the command's name.
$ type cd
cd is a shell builtin
$ type ls
ls is aliased to `ls --color=auto'
$ type -a python3
python3 is /usr/bin/python3
Tip

man pages are dense but predictably organized: NAME, SYNOPSIS, DESCRIPTION, OPTIONS, EXAMPLES. Many people jump straight to the bottom — G in the pager — because the EXAMPLES section is often all you need.

Four keys that pay for themselves today

  • Tab — completes commands, filenames, and paths. Press it constantly. Press it twice to see all matches. This is not a convenience feature; it is your defense against typos in destructive commands.
  • ↑ / ↓ — walk back through commands you already ran.
  • Ctrl-C — kill the command that is currently running. Use it when something hangs.
  • Ctrl-D — end of input. On an empty prompt it logs you out of the shell.
Careful

The shell has no undo and no recycle bin. rm means gone. The habit that saves you: type the command with ls first, look at what it matches, then change ls to rm by pressing ↑ and editing. Chapter 3 goes deeper.

Lab 1 · Orientation
  1. Open a terminal. Print your current directory, your username, and the machine's name (hostname).
  2. Find out whether echo is a builtin or a program on disk.
  3. Use ls --help to find the flag that sorts files by modification time, then run it on your home directory.
  4. Open the manual for date, search inside it for the string %Y, and use what you find to print today's date as 2026-08-14.
  5. Type sleep 60, then get your prompt back without waiting a minute.

Questions

What is the difference between a shell builtin and a regular command?

A builtin is implemented inside bash itself (cd, export, echo, test); a regular command is a separate executable file the shell finds and runs (ls at /usr/bin/ls). It matters for two reasons: builtins have no man page (use help), and only builtins can change the shell's own state — which is why cd must be a builtin. An external program could never change your shell's current directory.

Why does ls -lah work but ls --human-readable-all not?

Single-dash short options are single characters, so bash-era tools let you bundle them: -lah is parsed as three separate flags. Double-dash long options are whole words and each needs its own --: ls --human-readable --all.

You typed a long command and it is hanging. What do you press, and what if that does not work?

Ctrl-C sends the interrupt signal (SIGINT) and stops most programs. If the program ignores it, Ctrl-Z suspends it and gives you your prompt back, after which you can kill it (Chapter 9). If your terminal itself is garbled rather than hung, reset repairs it.

What does ~ mean, and what is ~/projects?

~ expands to your home directory, typically /home/yourname (or /Users/yourname on macOS). So ~/projects is /home/dave/projects. ~otheruser expands to that user's home directory. The expansion is done by the shell before the command ever sees it.
