Chapter 3Creating, Copying, Destroying

Six commands cover essentially all file management: mkdir, touch, cp, mv, rm, ln. They are simple. The care goes into not destroying things.

Creating

$ mkdir reports                 # one directory
$ mkdir -p a/b/c                # create parents as needed; no error if it exists
$ touch notes.txt               # create an empty file, or update its timestamp
$ touch f{1..3}.txt             # f1.txt f2.txt f3.txt

-p is worth a habit. It makes mkdir idempotent: running it twice is harmless, which is exactly what you want in a script.

Copying and moving

$ cp notes.txt notes.bak            # copy to a new name
$ cp notes.txt ~/backup/            # copy into a directory, keeping the name
$ cp -r project/ project-copy/      # -r for directories (recursive)
$ cp -a project/ project-copy/      # -a: recursive AND preserve times, owner, permissions
$ cp -i important.conf /etc/        # -i: prompt before overwriting
$ mv draft.txt final.txt            # rename
$ mv *.log logs/                    # move many files into a directory
$ mv -n a.txt b/                    # -n: never overwrite

mv is both "rename" and "move" — on the same filesystem it just rewrites a directory entry, which is why moving a 40 GB file within one disk is instant while copying it is not.

The trailing-slash trap

cp -r src dest behaves differently depending on whether dest already exists: if it does, you get dest/src; if it does not, src is copied to dest. When you care about the distinction, use rsync, whose rules are explicit: rsync -a src/ dest/ (with the trailing slash on the source) copies the contents.

Deleting, carefully

$ rm oldfile.txt
$ rm -r olddir/            # recursive: directory and everything inside
$ rm -f stubborn.txt       # force: no prompts, no error if missing
$ rmdir emptydir/          # only works if the directory is empty — a useful safety net

There is no trash can. rm unlinks the file and the space is reclaimed. Three habits that prevent almost every accident:

  1. Look before you delete. Run the pattern with ls first, then press ↑ and change ls to rm.
  2. Never type rm -rf with a variable or a glob you have not just inspected. rm -rf "$DIR"/* where $DIR is accidentally empty means rm -rf /*.
  3. Prefer rmdir when you expect empty. If it refuses, something is in there you did not know about.
$ ls old_reports_*.csv          # 1. inspect
old_reports_2024.csv  old_reports_2025.csv
$ rm old_reports_*.csv          # 2. same pattern, now with rm
Tip

Adding alias rm='rm -i' to your .bashrc is tempting but teaches you to reflexively hit y, which is worse. A better habit: put junk in /tmp so it cleans itself up, and use -i deliberately when it matters.

Links

$ ln -s /var/log/nginx/access.log access.log   # symbolic link (a pointer by path)
$ ls -l access.log
lrwxr-xr-x  1 dave  staff  29 Aug 14 09:20 access.log -> /var/log/nginx/access.log
$ ln data.csv data-hard.csv                    # hard link (a second name for the same data)

A symlink points at a path; if the target moves, the link breaks. A hard link is a second directory entry for the same underlying data, so the data survives until every name is removed. In practice you will use symlinks ninety-nine times out of a hundred — for pointing current at release-2026-08-14, for instance.

Batch operations

$ cp *.txt backup/                     # everything matching, into a directory
$ mv report_*.pdf 2026/                # tidy by pattern
$ for f in *.jpeg; do mv "$f" "${f%.jpeg}.jpg"; done   # rename extensions in bulk

That last one uses a loop and parameter expansion — both covered in Chapter 11. It reads as: for each file ending in .jpeg, move it to the same name with the .jpeg suffix stripped and .jpg appended. Note the quotes around "$f": without them, a filename with a space breaks the command.

Questions

Why does mkdir -p matter in scripts?

Without -p, mkdir fails with a non-zero exit code if the directory already exists, which will abort a script running under set -e. With -p it succeeds silently whether or not the directory is there, and creates any missing parent directories. That property — same result no matter how many times you run it — is called idempotence and is the backbone of reliable automation.

What is actually different between cp -r and cp -a?

-r copies the tree but the copies get fresh timestamps and your ownership/umask. -a ("archive") is -r plus preservation of modification times, permissions, ownership, and symlinks (copying links as links rather than following them). Use -a for backups and deployments; -r is fine for scratch copies.

You run rm -rf $BUILD_DIR/* and BUILD_DIR was never set. What happens, and how do you prevent it?

The variable expands to nothing, so the command becomes rm -rf /* — it tries to delete everything on the system it has permission to touch. Prevention, in order of usefulness: set -u at the top of every script (unset variables become an error), always quote ("$BUILD_DIR"), and use ${BUILD_DIR:?BUILD_DIR is required} which aborts with a message if the variable is empty or unset.

Your symlink shows in red in ls output. Why?

It is broken — the path it points to no longer exists. Symlinks store a path, not a reference to the data, so moving or deleting the target leaves the link dangling. ls -l still shows you where it was pointing, and readlink -f link resolves it.

Why is moving a large file within one disk instant, but copying it slow?

mv within a single filesystem only updates directory entries — the file's data never moves. Across filesystems (say from your disk to a USB stick), mv has no such shortcut: it copies the data and then deletes the original, so it takes as long as cp.
