Chapter 7grep, sed, and awk

Three tools handle nearly all text manipulation: grep selects lines, sed edits lines, awk works with fields. Around them sits a supporting cast — sort, uniq, cut, tr — that does the simple jobs. You do not need to master any of these. You need a working subset, which is what follows.

Regular expressions, the 20% of them

All three tools speak regex. Here is the part that matters:

PatternMatches
.any single character
*zero or more of the previous thing
+one or more (needs grep -E)
?zero or one (needs grep -E)
^start of line
$end of line
[abc]any one of a, b, c
[^abc]any character except a, b, c
[0-9]any digit
\.a literal dot (backslash escapes)
a|ba or b (needs grep -E)
(ab)+grouping (needs grep -E)
{2,4}between 2 and 4 repetitions

Use grep -E (extended regex) so that +, ?, |, and () work without backslashes. Use grep -F when you want no regex at all — searching for a literal string containing dots or slashes.

$ grep -E '^ERROR' app.log                    # lines starting with ERROR
$ grep -E 'error|fail|panic' app.log          # any of three words
$ grep -E '[0-9]{3}-[0-9]{4}' contacts.txt    # a phone-shaped pattern
$ grep -E '^\s*$' file.txt                    # blank lines
$ grep -F '192.168.1.1' access.log            # literal, dots are just dots
Always single-quote your patterns

grep '$USER' file searches for the literal text $USER; grep "$USER" file searches for your username. Regex is full of characters bash also wants to interpret ($ * ? [ ] \), so single quotes are the default and double quotes are the deliberate exception.

sed: search and replace on a stream

Ninety percent of real sed use is one command, s for substitute:

$ sed 's/old/new/' file.txt          # first occurrence on each line
$ sed 's/old/new/g' file.txt         # every occurrence (g = global)
$ sed 's/old/new/gi' file.txt        # global, case-insensitive
$ sed -i 's/old/new/g' file.txt      # edit the file in place
$ sed -i.bak 's/old/new/g' file.txt  # in place, keeping file.txt.bak

The delimiter does not have to be /. When your text contains slashes, switch it:

$ sed 's|/usr/local/bin|/opt/bin|g' paths.conf

The other handful of sed features worth knowing:

$ sed -n '5p' file.txt              # print only line 5 (-n suppresses default printing)
$ sed -n '10,20p' file.txt          # lines 10 through 20
$ sed '/^#/d' config.conf           # delete comment lines
$ sed '/^$/d' file.txt              # delete blank lines
$ sed 's/^[ \t]*//' file.txt        # strip leading whitespace
$ sed '2i\inserted line' file.txt   # insert before line 2
$ sed 's/\(.*\):\(.*\)/\2:\1/' pairs.txt   # swap around a colon using groups

In the last example \( \) captures a group and \1, \2 refer back to them in the replacement. With sed -E you can drop the backslashes: sed -E 's/(.*):(.*)/\2:\1/'.

On macOS

macOS ships BSD sed, where -i requires an argument: sed -i '' 's/a/b/' file. GNU sed (Linux) treats -i '' as an error. If you write scripts for both, sed -i.bak works on both and leaves a backup you can delete.

awk: columns and arithmetic

awk splits each line into fields and lets you work with them. $1 is the first field, $2 the second, $0 the whole line, NF the number of fields, NR the current line number.

$ awk '{print $1}' access.log              # first column
$ awk '{print $1, $NF}' access.log         # first and last column
$ awk -F, '{print $3}' data.csv            # comma as the separator
$ awk -F: '{print $1}' /etc/passwd         # all usernames
$ awk 'NR > 1 {print $2}' data.csv         # skip the header row

Add a condition before the braces and awk becomes a filter with arithmetic:

$ awk '$3 > 100' data.txt                     # lines where field 3 exceeds 100
$ awk -F, '$2 == "ERROR" {print $1}' log.csv  # field 2 matches exactly
$ awk '/timeout/ {print NR": "$0}' app.log    # regex match, printing line numbers
$ awk 'length($0) > 80' file.txt              # lines longer than 80 characters

And the thing awk does that nothing else does as cleanly — summing a column:

$ awk '{sum += $3} END {print sum}' sales.txt
48211
$ awk -F, 'NR>1 {sum += $4; n++} END {printf "avg: %.2f\n", sum/n}' data.csv
avg: 132.47
$ awk '{count[$1]++} END {for (ip in count) print count[ip], ip}' access.log | sort -rn

BEGIN { } runs before the first line, END { } after the last. That last example builds a frequency table in an associative array — it is the awk version of sort | uniq -c, and it is faster because it does not sort.

sort, uniq, cut, tr

$ sort names.txt                # alphabetical
$ sort -n numbers.txt           # numeric
$ sort -rn numbers.txt          # numeric, descending
$ sort -h sizes.txt             # human sizes: 2K < 1M < 3G
$ sort -u names.txt             # sorted, duplicates removed
$ sort -t, -k3 -n data.csv      # by 3rd comma-separated field, numerically
$ sort -k2,2 -k1,1 file.txt     # by field 2, then field 1

$ uniq file.txt                 # collapse ADJACENT duplicates — sort first!
$ uniq -c file.txt              # prefix each line with its count
$ uniq -d file.txt              # only lines that were duplicated
$ uniq -u file.txt              # only lines that appeared once

$ cut -d, -f2 data.csv          # field 2, comma-delimited
$ cut -d, -f1,3 data.csv        # fields 1 and 3
$ cut -d: -f1 /etc/passwd       # usernames
$ cut -c1-10 file.txt           # characters 1 through 10

$ tr 'a-z' 'A-Z' < file.txt     # uppercase
$ tr -d '\r' < dos.txt > unix.txt   # strip carriage returns
$ tr -s ' ' < file.txt          # squeeze runs of spaces into one
$ tr ' ' '\n' < file.txt        # one word per line
The rule that trips everyone

uniq only removes adjacent duplicate lines. It is a streaming tool with no memory. Always sort first: sort file | uniq -c. If you forget, you get a wrong answer rather than an error, which is worse.

Questions

Why must you sort before uniq?

uniq compares each line only to the one immediately before it — it holds no state beyond that, which is what lets it stream a file of any size. Duplicates scattered through the file therefore survive. sort brings identical lines together first. (sort -u does both in one step, but does not give you counts, so sort | uniq -c stays useful.)

When is cut the wrong tool and awk the right one?

When fields are separated by runs of whitespace of varying width — the output of ls -l, ps, or df. cut -d' ' treats every single space as a delimiter, so a double space produces an empty field and the columns shift. awk's default splitting collapses runs of whitespace, so awk '{print $5}' just works. Use cut for clean single-character delimiters like CSV or /etc/passwd.

How would you replace a string across every .conf file in a tree?

find . -name "*.conf" -exec sed -i.bak 's/old/new/g' {} +. Two safety notes: run it first without -i to see the substitutions printed, and the .bak suffix means every file gets a backup you can restore from — and then have to clean up with find . -name "*.bak" -delete.

What does awk 'NR > 1' do, and why is it so common?

NR is the current record (line) number, and a bare condition with no action block means "print the line". So NR > 1 prints everything except line 1 — it skips the header row of a CSV. The companion idiom is NR == 1 to print only the header.

Your regex grep '192.168.1.1' matches lines you did not expect. Why?

. in a regex matches any character, so that pattern also matches 192a168b1c1 and, more realistically, 192.168.1.100 as a substring. Either escape the dots (grep '192\.168\.1\.1'), anchor it with -w, or use grep -F to turn regex off entirely.

What is the awk equivalent of sort | uniq -c, and when is it better?

awk '{c[$1]++} END {for (k in c) print c[k], k}'. It is better on very large inputs, because it makes one pass and holds only the distinct keys in memory, whereas sort must order every line. The tradeoff is that the output is unordered, so you usually append | sort -rn anyway — on a modest file, the simpler sort | uniq -c is the better choice for readability.
